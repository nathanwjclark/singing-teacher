# TongueSAM pretrained baseline

The app now ships TongueSAM's public **YOLOX tongue prompt detector** as an ONNX asset. When the private personal tongue network is absent (HTTP 404), or the server refuses it because the browser is on another device such as a paired phone (HTTP 403), it loads automatically, and the tracker diagnostic names the cause. Only the personal manifest's status decides: a partial install (manifest present, weights missing) is reported as an error rather than silently replaced. It requires no user labels, personal training, Python service or paid model calls. The camera crop stays in the browser.

This is a visible-tongue **bounding box**, not the full TongueSAM surface segmentation model. Region-only observations never drive the 3D tongue-tip animation. They contain no inferred tip or depth: `TongueRegionObservation` (`src/types.ts`) carries only `box`, `confidence` and `observedAt`, so no consumer can read pose fields from it. The camera overlay, the side anatomy panel and Tongue Lab label region mode separately from tip mode. Phone snapshots store a region as `visibleTongueRegion`, never as `landmarks.tongue`; the server (`server/tongueSnapshot.mjs`) and the scientific fitters (`observed_landmarks` in `singing_physics/joint.py`) accept a tongue landmark only as a well-formed tip observation and reject any box or non-tip mode. The fitters also accept tips stored before `trackingMode` existed, when their fields form a well-formed tip, so older captures still replay. Existing personal tip weights, when installed, retain precedence.

## Provenance and reproduction

Upstream: https://github.com/cshan-github/TongueSAM at `3f6e8c620e4d89e669a92a22f3be3d007932ce45`, file `segment/yolox.pth`. Its public checkpoint SHA-256 is `a4f83fa8aeb47074ceb31d2b4c9823d4a8d574b5cdc6f7c6db68d16398fa3d3b`.

`scripts/export-tonguesam-detector.py --source <clean pinned checkout> --output <new output directory>` loads tensor-only weights, exports decoded normalized boxes, and verifies PyTorch/ONNX numerical agreement on all twelve upstream example images. It preserves the published 448-pixel input, ImageNet normalization and 0.7 objectness-times-class threshold; the browser reads the threshold and normalization from the manifest. The browser uses the highest-scoring valid box in the mouth crop; no class probabilities or calibration claims are inferred from that score.

The exported artifact and SHA-256 manifest are under `public/models/tonguesam/`. The app checks the manifest's hash format and verifies the file's hash before loading. If the file still fails after one fresh download, loading stops with an error and is not retried until the page reloads. The manifest is revalidated on every load; the weights use normal HTTP caching, and a cached copy that fails the hash is fetched once more before loading fails. Accompanying MIT/Apache license texts and NOTICE identify TongueSAM/Shan Cao and the Megvii YOLOX architecture. No public-example images or private training data are redistributed. `smoke-results.json` holds the exported ONNX model's output on the twelve upstream examples (image hash, box, score). The export script compares each output with PyTorch and stops on disagreement, but the rows record only the ONNX output; they are not accuracy. Upstream does not document which data trained `segment/yolox.pth`; its README names TongueSet1 (private), TongueSet2 (BioHit) and TongueSet3 (from Baidu AI Studio) for the segmentation model and states no licence for them. NOTICE records this. Export environment used Python 3.12, torch 2.14.0, torchvision 0.29.0, onnx 1.22.0, onnxruntime 1.30.0, Pillow 12.3.0 and NumPy 2.5.3; these are offline developer dependencies, not app startup requirements.

## Runtime behavior

The 34 MiB model loads lazily after the absent-private-model check. ONNX inference runs in a dedicated worker, with one in-flight frame in the existing tracker. Loading the model has a 60-second timeout and each inference 15 seconds, each reported as a timeout; repeated failures pause tongue inference until camera restart. Capture continues. A result becomes current on the first frame after it arrives. It stays current for its own inference latency plus 800 ms (300 ms for personal tip results), so the next result replaces it even on slower devices, while a stalled model still expires. `observedAt` keeps the acquisition time for lag reporting. Each result is mapped into the frame with the mouth crop of the frame it was computed from; edge round-off is clamped, and a result whose crop left the image, or whose box collapses, is reported and not used (neither a detection nor an abstention), so a held result does not shift when the head moves. Tongue Lab clips a held box to the saved crop and records no region when the two no longer overlap. Loss of the face invalidates pending results immediately. The tracker diagnostic reports `capability` (`region` or `tip`) and `abstained`, which is true only while the current result found nothing; Tongue Lab records `regionPrediction: null` only in that case, and records no region for frames where no current result exists. Camera shutdown terminates the worker.

Actual browser checks detected a region in an upstream example, rejected a uniform gray frame, and confirmed region output cannot move the anatomical tongue tip. Worker inference took roughly 0.38–0.43 seconds per frame on this Mac. This is a few-Hz region estimate, not high-rate motion capture. Public-example execution and export agreement are not independent singer/session accuracy tests.

## Full segmentation remains a separate step

TongueSAM's official README links the fine-tuned `tonguesam.pth` mask checkpoint through Baidu. The browser site-safety policy blocked access to that host in this environment. No bypass was attempted, and no alternate author-published checkpoint was found in the search. Its detector checkpoint is independently available directly in GitHub and is the only learned artifact used here.

Obtaining the author's segmentation checkpoint through an allowed source would enable the full box→SAM-mask stage. A generic SAM replacement would be a different baseline and must be labeled and evaluated separately. Neither that replacement nor the unavailable fine-tuned mask has been silently substituted. The intended product requires no user CV-model training; any future improvements should be developed and tested centrally before release.

## Integration review and acceptance

The preserved commits were integrated against main `304ee87`. A fresh download of the pinned `segment/yolox.pth` matched the source hash above, the shipped ONNX matched `128e78130f5b168ca4cb7580f1a3528d0625717f0294648020f0f5c5791da4c8`, and the bundled MIT text matched the [pinned upstream license](https://github.com/cshan-github/TongueSAM/blob/3f6e8c620e4d89e669a92a22f3be3d007932ce45/LICENSE.md) byte for byte. The [upstream paper](https://arxiv.org/abs/2308.06444) describes a prompt generator plus a mask decoder; the prompt detector alone must not inherit the full segmentation system's published accuracy claims.

The integration fixes preserve region bounds and acquisition timestamps in Tongue Lab exports, report box IoU independently of tip and segmentation metrics, retain the region overlay on frozen frames, and prevent motion calibration from inventing elevation or extension for a region-only observation. Missing models still permit capture and human labeling.

Verification: `tests/tongue-runtime.spec.ts` runs in the default Playwright suite (`npx playwright test`). It fetches the pinned public example `data/test_in/1.jpg` and checks its SHA-256 (set `TONGUE_PUBLIC_FIXTURE=<path>` to use a local copy; the image is not committed). It runs the real tracker, worker and components against a canvas stream of that image, with `/api` proxied to the real app server: the server's 404 for the absent personal model triggers the baseline; a region stays continuously visible for 4 s across about ten results; after the mouth crop moves, a result computed on the old crop keeps the old mapping and later results use the new one; calibration, freeze, independent surface/hidden-tip labels, a gray-frame abstention (`regionPrediction: null`) and export follow; a 403 personal-model answer still loads the baseline and says why; a partial personal install is reported as an error; weights that fail verification twice stop loading without a third download on camera restart; and with no model at all, or with the manifest present but the weights missing, capture and labeling continue with no region recorded. A second test posts phone snapshots to the real server. It recorded a region score of 0.9631 and about 0.37–0.40 s per inference on this Mac. Zero page errors and console errors are required, apart from the browser's resource-load notices for the model responses the test makes unavailable. This is public-example execution evidence, not held-out accuracy or device performance.

Remaining evidence: independent singing-session labels, an actual private tip/depth checkpoint if that capability is desired, and the author's full mask checkpoint. A detector bounding box never becomes a visible contour, tongue-tip position, depth measurement, or interior physiological constraint merely by being displayed or exported.
