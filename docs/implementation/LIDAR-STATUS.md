## Use

Enable `LIDAR_PREVIEW_ENABLED=1` and `LIDAR_FUSION_ENABLED=1` once when starting `npm run science:local`. Native rear capture remains independently optional. The rear camera never owns the microphone and records a separate held pose.

In **Experiments → Experimental rear LiDAR comparison**, use the latest pulled rear archive. Select its original depth frame and upper/lower outer-lip pixels; declare the pixel-reference mapping, held pose, finite jaw alternatives/weights, uncertainty and correspondence assumptions. These are app controls, not per-attempt backend files or commands. Declare synthetic fixtures as development evidence. Submit the comparison and inspect both rankings and the authoritative adoption result. **Apply depth-ranked model preview** loads the actual adopted native geometry only if its model identity and file hashes still match.

The observation is metric distance between explicitly corresponding outer-lip markers (native surfaces 4/5, vertex 89). Rigid distance invariance avoids inventing an unmeasured camera-to-head transform; it does not validate the landmark correspondence. Up to 32 retained anatomies × three declared jaw states require at most 96 geometry calls. Measurement/model sigmas and jaw weights are assumptions. A declared numerical equivalence rule retains acoustic order for indistinguishable predictions. All anatomy alternatives remain; these are not calibrated posterior probabilities.

The ordinary voice search now varies palate length and lip width. Its complete two-dimensional initial design uses 60 synthesis calls, explicitly increased from 36; five retained anatomies, forecasts and two geometry exports total 77 synthesis calls. Existing palate-only models can correctly yield tied depth predictions. They are never changed by inventing a distinguishing measurement.

## Recovery and provenance

Original archives and declarations are retained privately. The numerical worker verifies original depth before ranking; session adoption verifies it again. A successful numerical ranking is not an applied model unless the authoritative adoption receipt says so. Rejected attempts retain reasons. Reusable camera calibration is provenance, not a new independent measurement.

The last successful result remains available across failed later attempts and restart. Adoption is saved before optional geometry export; an export failure cannot disguise a successful model update as an unchanged baseline. Historical geometry cannot replace a newer current preview. Astra receives the contribution with scan identity, source kind, uncertainties and adoption-time verification; it is not described as a live scan. Session export includes the authoritative ledger and bound derived receipts after checking retained archive bytes, within export limits.

## Verification scope

Actual native-engine tests exercise original synthetic depth → projection → likelihood → changed or tied ordering, with baseline preservation, malformed/filtered/missing calibration rejection, budget limits and engine restoration. Session and app tests cover adoption, stale forecasts, original-byte changes, rejection, geometry export and restart. Browser checks inspect the actual app consumer separately from mathematical tests.

The existing native Swift sources parse and project plist validation passed previously. This host lacks the full iOS SDK: parsing is not an iOS build. No physical phone capture, sensor comparison, physiological accuracy or recovered hidden cavity is claimed.
