# Local scientific jobs, model preview and USB capture

The private desktop server now connects PR #6's real `JobService` to the app. `science/scripts/live_capture_jobs.py` verifies original native PCM through the existing importer, selects the earliest two eligible voiced windows under its recorded protocol, runs bounded `search_pcm`, freezes hypotheses, runs prospective `design_pcm`, and exports native geometry through a `forward` job. Every job result is verified by the scientific service before its artifacts are copied for display. Failures and partial outputs remain private. A complete run uses at most 46 native calls under the current protocol.

The current voice protocol assumes a prompted `a`, jaw −3°, observed calibration F0 and an explicit digital-gain grid. It searches only hard-palate length; all other anatomical parameters remain at the native reference. Prospective `a/e/i` predictions declare F0=180 Hz and gain=4. These assumptions and low-dimensional feature discrepancies do not identify anatomy, microphone/room response, hidden tissue or shoulder muscles. No later human forecast target is claimed scored. The model previews are static predicted geometry under declared articulation, separate from camera-driven reference anatomy.

`Experiments → Scientific model` displays actual retained job results and predicted acoustic features. `Model` in the movement-map controls loads SHA-256-verified native OBJ geometry and its matching sagittal SVG. It does not warp the teaching skeleton into a purported patient scan. `Default` restores live camera-driven anatomy. The calibrated foreground tongue motion uses shared kinematics; its scientific uncertainty remains separate from the image tracker.

Private configuration (never commit): `.local-data/science-input.json` contains `sourceDirectory`, relative to `.local-data`; `.local-data/iphone-device.json` contains the connected CoreDevice `deviceId`. The source must be an already authorized voice capture with the prompted vowel matching the protocol. USB import does not silently relabel arbitrary tongue videos as singing calibration. Native model results are in `.local-data/science-runs/<run-id>`; the current receipt is `.local-data/science-current.json`. The trained tongue profile is served from the fixed private `.local-data/tongue-review/live-tip-profile.json` file.

Scientific status/assets, the tongue profile, and USB routes are restricted to loopback clients. Browser cross-origin writes are rejected. Scientific POST runs a fixed local protocol, accepts no client paths or parameters, permits one active job, uses subprocess arguments rather than a shell, and retains failure logs. The HTTP layer provides no public tunnel. A server shutdown terminates its scientific process group; stale running receipts report interrupted after restart.

`Pull iPhone` lists completed ZIPs in the configured app container using Apple's devicectl JSON output, selects the newest, copies over the trusted device connection and verifies native capture archives. It preserves phone originals. Already copied files are size-checked and reverified; linked sessions and probe archives are retained without claiming RGBD verification. Locked/unavailable phones produce an actionable status. USB files stay under `.local-data/usb-imports` with receipts. Before copying, the pull runs `xcrun devicectl list devices --json-output` and refuses with 503 if the configured `deviceId` is not listed. The latest receipt, `.local-data/native-pull-latest.json`, has `schemaVersion: "native-pull-receipt-2"`, the archive `name`, `bytes` and `sha256`, and an `acquisition` record: `transport: "devicectl"`, `connection` (`transportType`, `wired` or `localNetwork`, and `tunnelState`), `container` (app data container, bundle id, file path) and `device` (`coreDeviceId`, `udid`, `productType`, `osVersion`). A field devicectl does not report is stored as null. `signature` is always `{status: "not-provided"}`: the receipt is written by this Mac and is not signed by the phone. The devicectl field names follow Flutter's `core_devices.dart` and appium's `node-devicectl`; they have not yet been checked against a phone on a Mac with full Xcode. `Reset tracking` saves any active browser recording, recreates the vision/motion state and depth baseline, and clears cues; it preserves existing recordings, model jobs and the learned profile.

Validation stays focused: actual human-source native jobs, private API/profile loading, rejected cross-origin and duplicate-job requests, actual device list/cached-capture verification, browser model/side geometry rendering and Reset/USB interactions, plus build/lint. No physiological accuracy or hidden-tip recovery is implied.
