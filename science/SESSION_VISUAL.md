# Conditional visual session lifecycle

`forecast_visual` takes `forecast_id` and `parameters` containing camera_candidates, calibration_frames, targets, coordinate_system, optional calibration_tolerance_px and max_geometry_calls. Standard command_id and expected_version are required. The session injects current model identity, all retained geometries and native provenance. Its isolated freeze_visual_forecast worker calibrates fixed camera candidates and freezes target predictions before annotations are accepted. There is no extra queue.

`score_visual` takes forecast_id and parameters containing annotations. Every frozen target needs an explicit annotation, including missing/occluded frames. Original video hash plus frame index defines physical identity. Calibration and target frames are disjoint; previously committed calibration/target frames cannot become new held-out targets. Annotation creation time must follow the durable session commitment. These may be previously captured videos: this is annotation holdout, not a claim of prospective capture. Original-byte and decoder verification belongs to the app import adapter; this session layer validates the supplied immutable lineage and worker artifacts.

State.visual_forecasts stores {artifact:{artifact,sha256},baseline_model_id,baseline_snapshot_sha256,committed_at,status,score_result?}. Status is committed, unsupported, score_pending, scored, unscorable or stale. State.visual_receipts retains numerical jobs and result hashes. Failures preserve baseline anatomy. Camera/articulation assumptions and comparative scores never replace the baseline model or calibrated uncertainty. A changed baseline invalidates active visual forecasts; hashes and command identities support restart/replay without refitting an already committed target.
